## What Phase B delivered

The PHP code generated by Propel's Active Record / Query / TableMap builders is now PHP 8.3-shaped: typed properties, return types, backed enums for ENUM columns, declare(strict_types=1) at the top of every emitted file, modernized builder code internally. All while keeping the BC contract intact via the `: self` covariance choice and the per-task golden-diff regen discipline.

### Generated-code shape changes

Every file emitted by the generator now has:

1. **`declare(strict_types=1);`** — enforced strict-type semantics in consumer codebases.
2. **Typed properties** — `protected ?int $id = null;` for primitive PHP types; `protected ?Author $aAuthor = null;` for FK references; `protected bool $book_isLoaded = false;` for lazy-load flags; `protected bool $new = true;` etc. on base object attributes. Temporal columns (DateTime runtime values) and LOB columns (resource streams) deliberately stay untyped to preserve the runtime storage contract.
3. **`: self` return types on setters** — both per-column and per-FK setters. Picked over `: static` to avoid covariance burden on user subclass overrides; picked over no-return-type because the generated `return $this;` benefits from explicit covariance. Documentation honestly states that user-subclass overrides need a matching return type (Round 1 cycle 1 fix).
4. **`: ?ClassName` typed-nullable getters on FK getters** — covariant-safe.
5. **`: static` on generated `Query::create()` static factories** — the deliberate exception: static factories don't have LSP-with-instances semantics, so `: static` returns the subclass type from `MyBookQuery::create()` correctly.
6. **`: bool` / `: void` / `: mixed` / `: string`** return types on base object methods (`equals`, `getVirtualColumn`, `setVirtualColumn`, `exportTo`, `log`).
7. **Modern `__serialize`/`__unserialize`** instead of `__sleep`/`__wakeup` — wire-format BC break, documented in MIGRATION-FROM-PRE-AI.md.
8. **Backed PHP 8.1 enum classes** for every ENUM column. Naming: `<TablePhpName><ColumnPhpName>` (e.g., `BookStatus`). Setters accept `<EnumClass>|\BackedEnum|string|null` for BC; getters return `?BackedEnum`.

## Surprises and signals for future phases

1. **`: self` IS empirically an LSP fatal** for user subclasses overriding without a return type. Documentation in Phase A claimed otherwise; Round 1 reviewer caught the lie. The runtime decision is still right (better than `: static`); the documentation honesty is now reinforced.
2. **Versionable behavior emits a sibling enum** on the version mirror table. This forced the setter union type to widen to `\BackedEnum` (parent of all backed enums) so both the table's enum and the version-table's enum are accepted. Slightly less type-safe than ideal; revisit in Phase D when behavior-modifier refactor lands.
3. **`setup.sqlite.sh` skips rebuilds when config files unchanged.** Important note for tooling: always `setup.sqlite.sh` before `regen-golden.php` to ensure the build directory is fresh.
4. **`__serialize` wire-format BC break** — persisted serialized AR objects from prior Propel versions cannot round-trip. Migration guide instructs invalidate-on-deploy.
5. **6 STI-subclass query files** missed the `Query::create(): static` change in B.4.9. Round 2 reviewer caught via determinism re-run. Reminder that `regen-golden.php` must run AFTER every generator change AND the working tree status must be empty afterwards.
6. **B.3 EnumBuilder generates new public classes** in consumer namespaces. Naming choice was `<TablePhpName><ColumnPhpName>`. Could collide with existing user classes; consider Phase G option flag if reports surface.
7. **Mutator union-type widening (`\BackedEnum`)** is sub-optimal — narrower would be `<EnumClass>|<KnownSiblingEnum>|string|null`. Phase G can revisit.
