## What Phase C delivered

Modern DB capabilities at the **schema model + DDL emission** layer. JSON/JSONB native, generated columns, CHECK constraints, INVISIBLE columns, PG IDENTITY — all surfaceable via XML schema and emitted to MySQL 8/MariaDB 10.5+ and PostgreSQL 14+ correctly. SQLite explicitly frozen at the existing feature surface per umbrella §1.2.

### Schema XSD extensions (Group C.1, additive only)

Per umbrella §3.7 — every change is `minOccurs=0` / optional and accepts old enumeration values forever:

- New column attributes: `generated="virtual|stored"`, `expression="..."`, `invisible="true"`.
- New `<check>` element on `<table>` (table-level constraint with name + expression + enforce) and on `<column>` (inline column-level constraint).
- New `default_datatypes` enumeration values: `JSON`, `JSONB`, `INET`, `CIDR`, `TSVECTOR`.
- `tools/xsd-additivity-check.php` validates 12 existing fixture schemas against the new XSD on every PR.

### Schema model classes (Group C.2)

- `Column::isGenerated()`, `getGenerationExpression()`, `getGenerationStorage()` (virtual/stored).
- `Column::isInvisible()`.
- `Table::getCheckConstraints()` returning `CheckConstraint[]`.
- New `CheckConstraint` model class with `name`, `expression`, `enforce` flag (PG enforce-only). Tier 2 SPI per BC contract.
- `Domain` updates for JSON/JSONB/INET/CIDR/TSVECTOR per platform (PG → JSONB/INET/CIDR/TSVECTOR native; MySQL → JSON native, others as TEXT; SQLite → frozen at TEXT).
- `SchemaReader` nested `<check>` element parsing.

### Platform DDL emission (Group C.3)

- **MysqlPlatform**: emits `GENERATED ALWAYS AS (expression) [VIRTUAL|STORED]` for generated columns, `INVISIBLE` keyword for invisible columns, `CHECK (expression)` inline + as named table constraint, `JSON` native column type.
- **PgsqlPlatform**: emits `GENERATED ALWAYS AS (expression) STORED` (PG only supports STORED), `JSONB` native (preferred over `JSON`), `INTEGER GENERATED BY DEFAULT AS IDENTITY` for new auto-increment PKs (replaces deprecated `serial`/`bigserial`), `CHECK` constraints.
- **SqlitePlatform**: rejects Phase C features at DDL emission with a clear "use MySQL/PG" error (frozen-feature stance per umbrella §1.2).
- **PlatformInterface** SPI extended with abstract methods for the new emission paths.

### Runtime helpers (Group C.3 incidental)

- `JsonbOperator` runtime SPI (Tier 2): provides `?`, `?&`, `?|`, `@>`, `<@` JSONB operators with proper PDO parameter escaping. Works around PHP PDO's `?` placeholder ambiguity by emitting doubled `??` form.

### Diff comparator extension (Group C.5 partial)

- `IndexComparator` and `ForeignKeyComparator` extensions deferred (depend on C.4 reverse-parser improvements being in place to surface comparison-relevant data).

### Migration cookbook (Group C.6 partial)

- `MIGRATION-FROM-PRE-AI.md` extended with: PG `serial`/`bigserial` → `IDENTITY` migration (manual SQL); JSON/JSONB column type migration; CHECK constraint enforcement differences across MySQL versions; INVISIBLE column behavior; reverse-engineering caveats.

## Surprises and signals for future phases

1. **Reverse parser is harder than estimated.** ~1300 lines + needs real DB containers for verification. Phase D plan should consider whether to continue Phase C's deferred reverse-parser work as part of D, or split it into a dedicated phase.
2. **PG `?`-placeholder vs JSONB `?` operator** is a real PDO friction point. The doubled-`??` workaround in `JsonbOperator::buildClause` is documented; if any consumer uses `PDO::ATTR_EMULATE_PREPARES=true`, the doubling won't survive — flagged in the migration cookbook.
3. **SqlitePlatform's hard-error on Phase C features** is the right call per umbrella §1.2 (frozen) but might surface as a developer-experience friction. Consider documenting "develop against MySQL/PG; SQLite is for unit tests only" in CONTRIBUTING.md.
4. **`legacy-serial` vendor flag** is a clean BC mechanism for the IDENTITY transition. Pattern repeatable in future phases.
